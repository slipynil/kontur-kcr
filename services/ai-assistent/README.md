# ai-assistent

TypeScript-сервис по ADR-0022. В этом PR завершён шаг 2 гипотезы: инструменты
чтения, Skills, конфигурация провайдера. Публичные summary/chat/filter-query и
агент реализуются следующим PR. Сейчас публичный сервер отвечает только `/healthz`.

MCP: `http://127.0.0.1:8001/mcp`, Streamable HTTP, MCP 2026-07-28. Используется
per-request handler SDK v2 без сессий, БД и кэша клиентских данных. Порт MCP
слушает только loopback и не должен публиковаться через Docker/Gateway.

## Запуск и проверка

Node.js 26.12, `npm ci`, `npm run build`, `npm start`.
Проверки: `npm run typecheck`, `npm run lint`, `npm run test:coverage`.
Skills остаются в `skills/` рядом с `dist/` при упаковке сервиса.

| Переменная | По умолчанию |
|---|---|
| `ASSISTANT_PORT` | `8000`, интерфейс `0.0.0.0` |
| `ASSISTANT_MCP_PORT` | `8001`, интерфейс `127.0.0.1` |
| `AI_ASSISTENT_LOG_LEVEL` | `info` |
| `CLIENTS_ENDPOINT` | `http://clients:8000` |
| `OPERATOR_WORK_ENDPOINT` | `http://operator-work:8000` |
| `CLIENT_HISTORY_ENDPOINT` | `http://client-history:8000` |
| `ASSISTANT_UPSTREAM_TIMEOUT_MS` | `10000` |
| `ASSISTANT_PROVIDER_BASE_URL` | Не задан |
| `ASSISTANT_PROVIDER_API_KEY` | Не задан |
| `ASSISTANT_MODEL` | Не задан |

Адреса сервисов задаются без `/internal/v1`. Провайдер и модель не выбраны:
`createModel` создаёт адаптер OpenAI-compatible только при явной конфигурации
всех трёх параметров; иначе `ASSISTANT_UNAVAILABLE`. MCP работает без провайдера.
Другой API провайдера потребует соответствующего адаптера AI SDK после согласования.

## Договор с будущим агентом

Хост получает `X-User-Id`/`X-User-Role` от Gateway и передаёт их в HTTP-запросе
MCP. Для клиентских операций он добавляет `X-Assistant-Kcr-Code` из маршрута.
Этого заголовка нет в аргументах инструментов: модель не может выбрать клиента.
Публичные заголовки идентичности Gateway перезаписывает (ADR-0010).
Проверку видимости клиента Gateway выполняет до вызова ассистента.

- `get_client_card`: документы и текущее рабочее состояние; отсутствие цикла — null.
- `get_call_context`: факты, последние события и две записи журнала на исходный
  квартал. При неполной хронике точный номер звонка неизвестен; выполнение
  обещаний требует сравнения наблюдений, автоматически не утверждается.
- `get_snapshot_history`: страница журнала. Без квартала — MCP `input_required`.
  Ответ переносится протоколом в новый запрос; decline/cancel не запускают чтение.
- `get_history_events`: страница хроники, квартал фильтрует `work_quarter`.
- `query_clients`: только ADMIN без клиентского scope; фильтры передаются Clients,
  exclude_tags/assignment применяются до limit по всем страницам. Возвращается
  ограниченная выборка и полный total. `work_quarter` пока возвращается в
  `not_applied`, поскольку API current-assignees читает только текущий цикл.

Хост должен использовать MCP-клиент с `versionNegotiation.mode.pin=2026-07-28`.
SDK по умолчанию использует legacy-протокол. Для паузы в UI агенту нужен ручной
режим input_required; автоматическое выполнение проверено интеграционным тестом.
Skills перечисляются через `SkillsClient.list()` и читаются с проверкой digest.
Результаты инструментов содержат только разрешённые поля, без контактов и
полных выгрузок. Ошибки не раскрывают тела ответов сервисов и адреса.

Приёмочные тесты используют настоящий HTTP MCP-клиент и тестовые внутренние API.
Облачная модель не вызывается; слепая бизнес-приёмка из §7 остаётся отдельным шагом.
