# Clients Service

Реализованы каркас FastAPI, конфигурация PostgreSQL, health endpoints, миграции Clients DB и локальное применение нормализованных пакетов Import по ADR-0004. Реализованы также чтение реестра, карточка, история и расчёты ADR-0005. Реализованы локальные rollback/delete по ADR-0006. Глобальная координация ещё не реализована. Миграции не запускаются автоматически при старте HTTP-приложения.

## Запуск через Docker Compose

Из каталога `services/clients`:

```powershell
docker compose up --build -d
docker compose logs migrate clients
Invoke-RestMethod http://localhost:8000/health/live
Invoke-RestMethod http://localhost:8000/health/ready
```

Compose поднимает PostgreSQL, применяет миграции отдельным заданием и запускает HTTP-сервис. Порты привязаны к localhost. Демонстрационные пароли предназначены только для локальной разработки. БД сохраняется в volume при `docker compose down`.

## Запуск Python локально

Python 3.13 и PostgreSQL 17. Из каталога `services/clients`:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.lock
.venv/Scripts/python.exe -m pip install --no-deps -e .
$env:CLIENTS_DATABASE_URL = 'postgresql+psycopg://clients:clients_local@localhost:5433/clients'
.venv/Scripts/alembic.exe upgrade head
.venv/Scripts/uvicorn.exe clients_service.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

Для запуска только БД можно использовать `docker compose up -d db`. `.env.example` содержит пример URL; приложение читает переменные окружения, файл `.env` автоматически не загружает. URL обязателен; секретное значение скрыто в представлении настроек. Валидационные ошибки настроек не следует публиковать в публичном API.

`/health/live` проверяет работу HTTP-процесса. `/health/ready` возвращает 200 при доступной БД с ожидаемой ревизией Alembic, иначе 503 с обезличенным ответом. Таймауты подключения и SQL задаются `CLIENTS_DATABASE_CONNECT_TIMEOUT` (секунды) и `CLIENTS_DATABASE_STATEMENT_TIMEOUT_MS`. Миграции используют тот же URL и таймауты.

## Проверки

```powershell
.venv/Scripts/ruff.exe check .
.venv/Scripts/python.exe -m pytest -m 'not postgres'
# PostgreSQL-проверки создают временную БД и удаляют только её.
# У пользователя тестового подключения должно быть право CREATE DATABASE.
$env:CLIENTS_TEST_ADMIN_URL = 'postgresql+psycopg://clients:clients_local@localhost:5433/postgres'
.venv/Scripts/python.exe -m pytest -m postgres
```

Без тестового URL интеграционные тесты явно пропускаются. Они проверяют upgrade/repeat/downgrade/upgrade, readiness, теги, ограничения и каскад внутри Clients DB; соседние сервисы не затрагиваются.

`requirements.lock` фиксирует runtime-зависимости, `requirements-dev.lock` — окружение разработки. Начальная миграция содержит замороженную копию утверждённого DDL; последующие изменения схемы оформляются новыми миграциями после обновления спецификации. Начальную миграцию после применения на общем стенде не менять.

## Применение пакета в изолированной разработке

По умолчанию `/internal/v1/import/apply` отсутствует и в маршрутах, и в OpenAPI. Для локальной проверки задайте `CLIENTS_ENABLE_IMPORT_APPLY=true` перед запуском Python-приложения. Настройка не заменяет авторизацию; в Compose она намеренно не включена. Межсервисную авторизацию нужно согласовать до открытия маршрута на общем стенде.

Пакеты REGISTRY создают/обновляют профили и теги. SNAPSHOT принимает только известные КЦР и сохраняет исходный квартал, остаток и историю. Пустой остаток наследуется из последнего наблюдения того же исходного квартала не позже даты нового среза; явный ноль снимает предупреждение. Более ранний срез дополняет историю, а исправление одной даты становится актуальным. Профиль обновляется по переданным полям; отсутствующие ключи частичного профиля не меняют данные. Явная пустота наследует известное поле и отмечает его для проверки.

Пример JSON конверта REGISTRY:

```json
{
  "batch_id": "00000000-0000-0000-0000-000000000101",
  "uploaded_by": "00000000-0000-0000-0000-000000000001",
  "selected_quarter": "2026_Q2",
  "import_type": "REGISTRY",
  "snapshot_date": "2026-04-20",
  "items": [{"client": {"kcr_code": "example-001", "organization_name": "Тестовый клиент"}}]
}
```

Для SNAPSHOT поменяйте batch_id, укажите import_type=SNAPSHOT и добавьте в строку `"snapshot": {"quarter": "2026_Q1", "total_documents": 100, "unsubmitted_documents": 7}`. Числа должны быть нормализованными целыми, без строк/boolean/дробей. Excel нормализует Import, а не этот сервис.

Ответ содержит счётчики, accepted_rows, rejected_rows и errors (индекс строки с единицы, код, поле). Непринятая строка не оставляет частичных изменений профиля. Повтор идентичного batch_id возвращает сохранённый ответ; другое содержимое с тем же ID возвращает 409. Идентичность файлов между разными batch_id обеспечивает Import.

Данные, результат и undo атомарны в одной PostgreSQL-транзакции. Все apply сериализуются локальным advisory lock; при ошибке БД операция отменяется и HTTP возвращает 503 для повтора того же пакета. Undo хранится в Clients DB; механизм выполнения отката будет отдельным этапом. Сохранённый локальный результат не означает завершения импорта в Operator Work.

Миграция 0002 расширяет схему исходного DDL без изменения ранее созданной миграции. Этап чтения и расчётов реализован по ADR-0005. Локальные rollback/delete реализованы по ADR-0006; далее — интеграция координатора и авторизация.

## Чтение в изолированной разработке

Задайте `CLIENTS_ENABLE_REGISTRY_READ=true` перед запуском Python-приложения. По умолчанию GET-маршруты ниже отсутствуют и не публикуются в OpenAPI. Настройка не заменяет авторизацию; в Compose она не включена.

```powershell
Invoke-RestMethod 'http://localhost:8000/internal/v1/clients?search=123&tags=VIP,INTEGRATOR&page=1&page_size=20'
Invoke-RestMethod 'http://localhost:8000/internal/v1/clients?quarter=2026_Q3&dynamics=REDUCING'
Invoke-RestMethod 'http://localhost:8000/internal/v1/clients/example-001?quarter=2026_Q3&snapshots_limit=8'
Invoke-RestMethod 'http://localhost:8000/internal/v1/clients/example-001/snapshots/history?quarter=2026_Q2&limit=20&offset=0'
```

Поиск — буквальное вхождение по КЦР/ИНН без учёта регистра. Все выбранные теги должны присутствовать одновременно; передавайте их одним параметром через запятую. Сортировка списка по КЦР стабильна. Неизвестные параметры (включая фильтры операторов), повторяющиеся ключи и неверные диапазоны возвращают 400. page_size — 1–100, page — 1–1000000; limit истории — 1–100, offset — 0–100000000; snapshots_limit — 1–50.

Динамика теперь сравнивает актуальные остатки разных исходных кварталов. По умолчанию — текущий календарный квартал по Москве и предыдущий. quarter выбирает другой период сравнения. Если одного из двух периодов нет, dynamics=null; отсутствие не заменяется нулём. В ответе dynamics_quarter, dynamics_previous_quarter, dynamics_current_documents и dynamics_previous_documents показывают основание расчёта. Например, за Q2 осталось 10, за Q3 — 20: dynamics=GROWING, даже если внутри Q3 остаток снижался. ALL_SUBMITTED означает ноль выбранного квартала при известной паре, а не отсутствие документов за все остальные периоды.

quarter в списке/карточке меняет пару сравнения, но не скрывает клиента без этого периода и не ограничивает суммарный остаток. В истории quarter — фильтр исходного периода, без него доступны все периоды. История имеет limit/offset/total, свежие даты и исправления первыми. Новый импорт между отдельными запросами страниц может сдвинуть их позиции.

Категории FIRST_TIME/REPEATED/LONG_DELAY_2Q определяются загруженными наблюдениями, календарь сам по себе не увеличивает длительность. Разные строки кварталов одного пакета на одну дату считаются одним наблюдением клиента. Полное обнуление завершает непрерывный период; после него новый остаток снова FIRST_TIME. Пропущенная строка не обнуляет старые остатки. Фильтры выполняются в PostgreSQL до подсчёта total и пагинации, без загрузки всей истории в Python.

Карточка не содержит назначения, этапы и сроки оператора: их агрегирует Gateway. raw_work_status, field_sources и undo в HTTP-ответы чтения не включаются. Суммарный остаток учитывает все исходные кварталы независимо от snapshots_limit. Несуществующий клиент возвращает 404, известный клиент без истории — пустой список с total=0. Ошибка БД возвращает обезличенный 503.

## Откат и удаление в изолированной разработке

После `alembic upgrade head` задайте `CLIENTS_ENABLE_DATA_RECOVERY=true` перед запуском Python-приложения. По умолчанию маршруты отсутствуют. Это переключатель разработки, а не авторизация; в Compose он не включён.

```powershell
$body = @{ operation_id = [guid]::NewGuid().ToString(); requested_by = '00000000-0000-0000-0000-000000000001' } | ConvertTo-Json
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body $body 'http://localhost:8000/internal/v1/import/00000000-0000-0000-0000-000000000101/rollback'
# Для каждого нового действия создавайте новый operation_id; при повторе сохраняйте прежний body.
$body = @{ operation_id = [guid]::NewGuid().ToString(); requested_by = '00000000-0000-0000-0000-000000000001' } | ConvertTo-Json
Invoke-RestMethod -Method Delete -ContentType 'application/json' -Body $body 'http://localhost:8000/internal/v1/clients/example-001/snapshots/2026_Q1'
```

Удаление клиента целиком: `DELETE /internal/v1/clients/{kcr_code}` с таким же телом команды. Отсутствующий объект успешно возвращает нулевые счётчики. Повтор одной команды возвращает прежний ответ даже после новой загрузки данных и не удаляет их повторно; другой payload с тем же operation_id даёт 409.

Откат возвращает состояние затронутых клиентов до импорта. По решению пользователя данные, вручную удалённые после пакета, тоже восстанавливаются. История сохраняет прежние ID и порядок; наблюдения отменяемого и ранее отменённых пакетов не возвращаются. Удаление до импорта и удалённые клиенты вне откатываемого пакета не отменяются.

Для этого удалённая история находится в закрытом undo, недоступном Registry API. Это обратимое административное удаление из рабочих таблиц. Необратимое уничтожение копий и срок хранения undo отдельно не согласованы. Повтор rollback уже отменённого пакета с новым operation_id возвращает already_rolled_back=true и не отменяет действия, выполненные после первого успешного отката.

Ответ local_only=true подтверждает только транзакцию Clients. Координатор Import должен проверить глобальный последний пакет, сериализовать глобальную операцию и согласовать очистку/восстановление Operator Work и кэшей. Полный протокол и ограничения: [clients-recovery-protocol.md](../../docs/clients-recovery-protocol.md).

Миграция 0003 добавляет монотонный порядок новых пакетов. Для пакетов старой схемы порядок не угадывается: единственный старый активный пакет допустим, несколько дают IMPORT_ORDER_UNKNOWN до установления достоверного порядка координатором. Для новых пакетов более ранний локальный откат запрещён (IMPORT_NOT_LATEST). Применение уже отменённого batch_id запрещено; новая загрузка требует нового ID.
