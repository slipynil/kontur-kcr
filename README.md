# Контур КЦР — контроль передачи оригиналов документов

Веб-система для команд, которые следят, чтобы корпоративные клиенты вовремя
передавали оригиналы документов. Она показывает, у кого из клиентов сколько
документов ещё не передано, помогает обзвонить таких клиентов и не потерять ни
одну договорённость.

Работа строится вокруг **Кода КЦР** — уникального номера клиента. По нему (или
по ИНН) клиент находится мгновенно, вместе со всей историей общения.

---

## Что система умеет

### 🔎 Общая таблица клиентов
Все клиенты в одном списке с поиском по Коду КЦР и ИНН. Цвет строки сразу
показывает ситуацию: 🟢 документы передаются или всё передано, 🟡 клиент с
непереданными документами впервые, 🔴 число непереданных растёт, ситуация
повторяется или просрочена, ⚪ без изменений.

Фильтры помогают быстро отобрать нужных: по динамике (уменьшается / растёт /
без изменений), по длительности (впервые / повторно / долго), по признакам
(VIP, новичок, интегратор, техпартнер, МПП).

### 📇 Карточка клиента
Полная история взаимодействия в одном экране: профиль и признаки, документы по
кварталам, как менялось число непереданных (журнал изменений), за кем закреплён
клиент, все звонки и комментарии — включая записи, внесённые задним числом.

### ✅ Список «Сегодня нужно»
Очередь на день, которая всегда наверху рабочего места оператора. Система сама
ставит в неё клиентов с истёкшим обещанным сроком и тех, чья ситуация ухудшилась
после новой загрузки данных. Ничего не теряется.

### 📞 Работа со звонками
Кнопка «Взять в работу» закрепляет клиента за оператором без конфликтов: если
клиент уже ведёт другой оператор, система сразу покажет, кто именно. Результат
звонка фиксируется в два клика: договорился / отказ / не дозвонился / неверный
номер + обещанный срок, если клиент его назвал.

### 📥 Загрузка данных из Excel
Администратор загружает файлы выгрузок — система сама разбирает их, сверяет,
отбрасывает дубликаты и проблемные строки (с отчётом, что именно и почему не
загрузилось). Если файл загружен по ошибке — импорт можно откатить одной кнопкой.
Число «всего документов» за квартал запоминается при первой загрузке и дальше
не меняется — история остаётся честной.

### 🤖 ИИ-ассистент
Перед звонком оператор видит готовую сводку «Контекст перед звонком» (5–7 строк:
состояние документов, динамика, история договорённостей). В чате можно задать
вопрос по клиенту — ассистент отвечает только на основе данных системы и
показывает, на какие события опирается. Отбор клиентов на обзвон можно задать
простыми словами: «Не VIP, непереданных больше 25%, без изменений».

### 👥 Роли
- **Оператор** — работает с клиентами: ищет, звонит, фиксирует результаты.
- **Администратор** — загружает данные, формирует списки на обзвон, снимает
  клиентов с операторов, управляет пользователями и ролями.

## Как это выглядит в работе

**День оператора:**
1. Вход в систему → наверху список «Сегодня нужно».
2. Звонок первому клиенту; перед звонком — сводка контекста.
3. «Взять в работу» → разговор → фиксация результата и обещанного срока.
4. Карточка клиента всегда под рукой: вся история, ничего не нужно искать по
   таблицам и почте.

**День администратора:**
1. Загрузка новой выгрузки Excel → сводка импорта: сколько строк загружено,
   сколько с ошибками и почему (можно скачать файл с ошибками).
2. Просмотр динамики по клиентам после загрузки.
3. Формирование списка на обзвон (в том числе «отбор словами» через
   ассистента) и передача его операторам.

## Цели, которые измеряем

| # | Метрика | Цель |
|---|---------|------|
| 1 | Узнать текущее состояние и историю клиента | до 1 минуты, 100% полноты |
| 2 | Обработать новый срез и собрать список на обзвон | 5–7 минут |
| 3 | Пропущенные повторные контакты | 0% |

## Безопасность данных

Данные клиентов (в том числе ИНН, контакты, тексты комментариев и содержимое
Excel-файлов) **не передаются во внешние сервисы**. ИИ-ассистент работает только
на локальной модели и отвечает исключительно по данным системы.

## Ограничения текущей версии

- интеграций с системами Контура нет — обмен данными через Excel-файлы;
- работа ведётся на тестовых данных;
- архитектура рассчитана на то, что позже импорт из Excel можно будет заменить
  загрузкой через API — без перестройки системы.

## Глоссарий

| Термин | Простыми словами |
|--------|------------------|
| КЦР | Код клиента в реестре заказчика; уникальный номер клиента в системе |
| ИНН | Идентификационный номер налогоплательщика |
| Срез | Снимок реестра на дату одной загрузки из Excel |
| Непереданные документы | Оригиналы документов, которые клиент ещё не передал |
| Динамика | Куда движется число непереданных документов: уменьшается, без изменений, растёт |
| «Сегодня нужно» | Очередь клиентов на текущий день: просроченные обещания и ухудшение динамики |
| ИИ-ассистент | Встроенный помощник: сводка перед звонком, ответы по истории клиента, отбор словами |

## Для технических специалистов

<details>
<summary>Архитектура, документация и структура репозитория</summary>

Система — микросервисная, контейнеры организованы по слоям Presentation →
Business → Persistence → Database; LLM и MCP Server — внешние инструменты вне
границы системы ([ADR-0001](docs/adr/0001-split-system-into-microservices-by-domain.md)).

Схема контейнеров: [C4 L2](docs/c4-l2-container-diagram.html) (открыть в браузере).

| Сервис | Отвечает за | Стек | Хранилище |
|--------|-------------|------|-----------|
| **Gateway / Identity** | Аутентификация, роли, маршрутизация запросов; намеренно тонкий | Go | Identity DB (PostgreSQL) |
| **Import Service** (Import API + Import Worker) | Приём и фоновая обработка Excel; единственное место, которое меняется при замене Excel на API | Python | Import DB (PostgreSQL) |
| **Clients Service** | Реестр клиентов, срезы, журнал изменений, динамика | Python | Clients DB (PostgreSQL) |
| **Operator Work Service** | Обзвон: закрепления, этапы, лента событий, «Сегодня нужно» | Python | Operator Work DB (PostgreSQL) |
| **Assistant Service** | Чат с ИИ-ассистентом, не привязан к конкретной модели | Python | — |

Инфраструктура: Web App (SPA), nginx (HTTPS), RabbitMQ (очередь задач импорта),
PostgreSQL (отдельная БД у каждого сервиса), LLM и MCP Server — внешние.
