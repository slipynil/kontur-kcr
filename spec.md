# Technical Specification (spec.md): Веб-сервис «Контур КЦР»

**Версия спецификации:** 1.1  
**Контекст проекта:** Сервис контроля передачи оригиналов документов корпоративными клиентами КЦР (АО «СКБ Контур»).  
**Связанные документы:**
- Правила ИИ и кодогенерации: `AGENTS.md`
- Архитектурная диаграмма: `docs/c4-l2-container-diagram.html`
- Архитектурные решения: `docs/adr/`
- Спецификации API (OpenAPI): `docs/api/`
- Модель данных и DDL: `docs/db/`
- Первичное бизнес-ТЗ: `ТЗ_Контур_КЦР_триплстар_v4.docx`

**Обязательная функциональность:** импорт клиентов и срезов без дублей; хранение истории изменения статуса передачи документов и автоматический расчёт динамики; общая таблица с фильтрами; механизм «взять в работу» без конфликтов между операторами; фиксация события «звонок»; список «Сегодня нужно»; карточка клиента с полной историей взаимодействия; поиск по коду КЦР и ИНН; разграничение ролей.

## 1. Системный контекст и архитектурные ограничения

### 1.1 Распределение сервисов (C4 Model Level 2 Alignment)
Система представляет собой микросервисную архитектуру, логически и технологически разделённую согласно `AGENTS.md`:

1. **Gateway / Identity Service (Go):**
   - **Зона ответственности:** Единственная точка входа (API Gateway), аутентификация/авторизация (JWT/Sessions), разграничение ролей RBAC (`ADMIN` / `OPERATOR`), проксирование REST/gRPC запросов к внутренним сервисам (включая агрегацию карточки клиента из Clients Service и Operator Work Service), контроль CORS и таймаутов.
2. **Clients Service (Python):**
   - **Зона ответственности:** Реестр клиентов (Код КЦР, ИНН, КПП, признаки через справочник тегов), управление статусами клиентов, хранение срезов по кварталам и **журнала истории изменения статуса передачи документов**, автоматический расчёт динамики, поиск по Коду КЦР и ИНН.
3. **Import Worker (Python):**
   - **Зона ответственности:** Фоновая асинхронная обработка Excel-файлов (`.xlsx`), парсинг, валидация по правилам КЦР (включая дедупликацию), логика сохранения/накопления срезов по кварталам без дублей, формирование отчёта об импорте и выявление проблемных строк, откат импорта.
4. **Operator Work Service (Python):**
   - **Зона ответственности:** Закрепление клиентов за операторами (атомарное, без конфликтов), этапы работы, лента событий карточки клиента (звонки, комментарии, письма, претензионная работа), формирование приоритетных списков и очередей «Сегодня нужно», работа с шаблонами писем, логика отбора базы под квоты.
5. **Assistant Service (Python):**
   - **Зона ответственности:** Локальный ИИ-ассистент. Генерация сводки «Контекст перед звонком» (5–7 строк), обработка естественного языка для «Отбора словами» при формировании пула на обзвон, ответы на вопросы по истории клиента strictly на основе контекста БД.

### 1.2 Критические правила безопасности и бизнес-ограничения
- **Zero External Data Leakage:** Никакие персональные данные, ИНН, файлы Excel или тексты комментариев не передаются во внешние API/LLM сервисы. ИИ-помощник использует исключительно локальный провайдер/модель.
- **Идентификатор клиента:** Первичным бизнес-ключом системы является **`Код КЦР`** (строка/ID). Один ИНН может иметь несколько уникальных Кодов КЦР.
- **Терминологический бан:** В API, интерфейсах, БД и комментариях ЗАПРЕЩЕНО использовать слова `долг`, `задолженность`, `должник`. Допустимы только `неотправленные документы` / `непереданные оригиналы документов`.
- **Импорт без дублей:** Один срез на пару (`kcr_code`, `quarter`) — повторная загрузка того же квартала обновляет только число непереданных документов и никогда не создаёт дубликат записи. Дубликаты строк внутри одного листа файла отсекаются при импорте.
- **Сохранность историчности:** Общее количество документов за квартал («Всего документов») фиксируется при первой загрузке квартала. При последующих срезах за этот же квартал меняется только число непереданных документов.
- **История изменения статуса передачи документов:** Каждое изменение числа непереданных документов при импорте фиксируется записью append-only журнала (значение, дата среза, пакет импорта). Журнал не редактируется и не удаляется (кроме каскадного отката пакета) и является основой автоматического расчёта динамики.
- **Race Condition Protection:** Фиксация клиента за оператором при нажатии «Взять в работу» должна быть атомарной на уровне БД (SELECT FOR UPDATE / ACID-транзакция / уникальный индекс активного закрепления).

## 2. Модель данных и сущности (Domain Model)

Полные DDL и связи — в `docs/db/`; между БД сервисов физические FK отсутствуют, связи логические.

### 2.1 Сущность `User` (Пользователь) — Identity DB
- `id`: UUID (PK)
- `login`: String (Unique)
- `password_hash`: String
- `role`: Enum (`ADMIN`, `OPERATOR`)
- `is_active`: Boolean
- `created_at`: Timestamp

### 2.2 Сущность `Client` (Карточка клиента КЦР) — Clients DB
- `kcr_code`: String (PK / Unique Identifier)
- `inn`: String (Indexed)
- `kpp`: String
- `organization_name`: String
- `status`: Enum (`ACTIVE`, `INACTIVE`)
- `is_blocked`: Boolean
- `manager_name`: String
- `contacts`: JSONB
- `raw_work_status`: String (исходный рабочий статус из выгрузки; хранится для истории и разбора, в UI не показывается)
- `source`: Enum (`REGISTRY`, `SNAPSHOT`) — откуда создан клиент
- **Признаки (Tags):** связь M:N со справочником тегов (`VIP`, `NOVICE`, `INTEGRATOR`, `TECH_PARTNER`, `MPP`, `DO_NOT_WORK`); новые признаки добавляются строкой справочника, без миграции схемы
- `created_at`, `updated_at`: Timestamp

Закрепление за оператором и этап работы — сущности Operator Work DB (§2.7, §2.8), не поля клиента.

### 2.3 Сущность `QuarterSnapshot` (Актуальный срез квартала) — Clients DB
- `kcr_code` + `quarter`: составной PK; `quarter`: String (`2026_Q1`, `2026_Q2`, …)
- `total_documents`: Integer (Запоминается при первом импорте квартала, далее не меняется)
- `unsubmitted_documents`: Integer (Обновляется каждым новым срезом того же квартала)
- `import_batch_id`: UUID (логическая ссылка на `ImportBatch.id`; последний пакет, менявший запись)
- `snapshot_date`: Date (дата последней загрузки)
- `created_at`, `updated_at`: Timestamp

Одна запись на (`kcr_code`, `quarter`) — актуальное состояние; логика upsert см. §3.2.

### 2.4 Сущность `QuarterSnapshotHistory` (Журнал истории изменения статуса передачи документов) — Clients DB
Append-only журнал: одна запись на каждое изменение числа непереданных документов при импорте.
- `id`: UUID (PK)
- `kcr_code`: FK -> `Client.kcr_code`
- `quarter`: String
- `unsubmitted_documents`: Integer (значение после изменения)
- `import_batch_id`: UUID (логическая ссылка на пакет, вызвавший изменение)
- `snapshot_date`: Date (дата среза)
- `created_at`: Timestamp

Первая загрузка квартала создаёт и запись `QuarterSnapshot`, и первую запись журнала. На основе журнала считаются динамика (§3.3) и «последние 3 среза» сводки ассистента (§3.4).

### 2.5 Сущность `ClientEvent` (Лента событий / Звонки / Комментарии) — Operator Work DB
- `id`: UUID (PK)
- `kcr_code`: String (логическая ссылка на `Client.kcr_code`)
- `author_id`: FK -> `User.id`
- `event_type`: Enum (`CALL_RESULT`, `HISTORICAL_COMMENT`, `EMAIL_SENT`, `STAGE_CHANGE`, `CLAIM_UPDATE`, `OPERATOR_ASSIGN`)
- `call_result`: Enum (`AGREEMENT`, `REFUSAL`, `NO_ANSWER`, `WRONG_NUMBER`) (Nullable, только для `CALL_RESULT`)
- `promised_date`: Date (Nullable)
- `comment_text`: Text
- `historical_event_date`: Timestamp (Заполняется оператором, если вносится прошлый комментарий)
- `created_at`: Timestamp

Лента append-only: события не редактируются и не удаляются.

### 2.6 Сущность `ImportBatch` (Журнал импортов) — Import DB
Один загруженный файл = один пакет.
- `id`: UUID (PK)
- `uploaded_by`: FK -> `User.id`
- `filename`: String
- `status`: Enum (`PROCESSING`, `COMPLETED`, `ROLLED_BACK`, `FAILED`)
- `total_rows`, `success_count`, `error_count`: Integer
- `created_at`, `completed_at`: Timestamp

Детальные строки ошибок хранятся в таблице `ImportErrors` (`batch_id`, `sheet`, `row_number`, `kcr_code`, `reason`) — основе виджета скачивания `.xlsx` с ошибками (§4.1). Для отката пакета Worker фиксирует undo-информацию (`ImportBatchUndo`: какие записи (`kcr_code`, `quarter`) пакет создал/обновил и каким было значение до).

### 2.7 Сущность `ClientAssignment` (Закрепление за оператором) — Operator Work DB
- `id`: UUID (PK)
- `kcr_code`: String (логическая ссылка)
- `operator_id`: FK -> `User.id`
- `assigned_at`: Timestamp
- `released_at`: Timestamp (Nullable; NULL = активное закрепление)
- `released_by`: UUID (Nullable)

Активное закрепление максимум одно на клиента (частичный уникальный индекс); история закреплений сохраняется.

### 2.8 Сущность `ClientStage` (История этапов) — Operator Work DB
- `id`: UUID (PK)
- `kcr_code`: String (логическая ссылка)
- `stage`: Enum (`POOL`, `IN_WORK`, `WAIT_DEADLINE`, `CLAIM`, `CLOSED`)
- `changed_by`: UUID
- `changed_at`: Timestamp
- `comment`: Text (Nullable)

Актуальный этап — последняя запись. Смена этапа дублируется событием `STAGE_CHANGE`, взятие в работу — `OPERATOR_ASSIGN` в ленте событий.

## 3. Спецификация микросервисов и API

### 3.1 Gateway / Identity Service (Go)
**Обязанности:**
- `POST /api/v1/auth/login` — аутентификация.
- `GET/POST /api/v1/users` — CRUD пользователей (только `ADMIN`).
- Проксирование запросов в Python-микросервисы с проверкой Bearer JWT и роли.

---

### 3.2 Import Worker (Python)
**Обязанности:**
1. **Парсинг Excel (.xlsx):**
   - Пропуск и отсев строк итогов (по ключевому слову `ИТОГО`).
   - Валидация строк без `Кода КЦР` -> отсев в ошибки импорта.
   - Проверка дробных значений документов и **дедупликация строк внутри одного листа** (повторный `kcr_code` в листе — отсев дубля).
   - Код КЦР из среза, отсутствующий в реестре клиентов, -> отсев в ошибки импорта.
   - Составные периоды реестра («2-4 кв 2025», «весь 2025 - 2 кв 2026») не поддерживаются моделью -> отсев в ошибки импорта.
2. **Логика дельты и первого сохранения (upsert без дублей):**
   - Если по `(kcr_code, quarter)` запись отсутствует -> записать `total_documents` и `unsubmitted_documents` + создать первую запись журнала истории.
   - Если запись существует -> `total_documents` НЕ перезаписывать, обновить только `unsubmitted_documents` (а также `import_batch_id`, `snapshot_date`) и добавить запись в журнал истории изменения статуса передачи документов.
3. **Отмена загрузки:**
   - `POST /api/v1/imports/{batch_id}/rollback` — каскадный откат срезов текущего пакета, если файл был загружен по ошибке: записи, созданные пакетом, удаляются; обновлённые — восстанавливаются по undo-информации; записи журнала истории, добавленные пакетом, удаляются. Статус пакета -> `ROLLED_BACK`.

---

### 3.3 Clients Service & Operator Work Service (Python)
**Обязанности:**
- `GET /api/v1/clients` — общая таблица (реестр) с параметрами фильтрации:
  - `search` (Код КЦР / ИНН)
  - `dynamics` (`REDUCING`, `NO_CHANGE`, `GROWING`, `ALL_SUBMITTED`)
  - `duration` (`FIRST_TIME`, `REPEATED`, `LONG_DELAY_2Q`)
  - `tags` (`VIP`, `NOVICE`, `INTEGRATOR`, `TECH_PARTNER`, `MPP`, `DO_NOT_WORK`)
- `GET /api/v1/clients/{kcr_code}` — карточка клиента с полной историей взаимодействия: профиль и теги, актуальные срезы по кварталам, закрепление, этап; лента событий и журнал изменений статуса передачи документов получаются подчинёнными эндпоинтами (агрегация данных Clients Service и Operator Work Service выполняется Gateway).
- `GET /api/v1/clients/{kcr_code}/events` — лента событий (пагинированная, свежие первыми).
- `POST /api/v1/clients/{kcr_code}/take` — взятие клиента в работу:
  - Проверка: если есть активное закрепление за другим оператором, возвращать `409 Conflict` с именем текущего владельца.
- `POST /api/v1/clients/{kcr_code}/events` — добавление события (звонок, прошлый комментарий с ручной датой `historical_event_date`).
- `GET /api/v1/operator/today` — вычисление очереди «Сегодня нужно»:
  - Клиенты с истёкшим `promised_date`.
  - Клиенты с изменившейся динамикой после нового среза.

**Автоматический расчёт динамики.** Динамика клиента рассчитывается автоматически по журналу истории изменения статуса передачи документов (§2.4): берутся две последние записи журнала последнего квартала клиента (`prev` -> `last`):
- `ALL_SUBMITTED` — `last.unsubmitted_documents = 0` (все переданы);
- `REDUCING` — число непереданных уменьшилось;
- `NO_CHANGE` — не изменилось;
- `GROWING` — выросло;
- не определена (`null`) — по последнему кварталу единственная запись журнала (первая загрузка; в UI — жёлтый «Впервые»).

Пересчёт выполняется при каждом добавлении записи журнала (импорте); результаты используются фильтром `dynamics`, цветовой индикацией (§4.2) и очередью «Сегодня нужно».

---

### 3.4 Assistant Service (Python)
**Обязанности:**
- `GET /api/v1/assistant/summary/{kcr_code}` — генерация текстового блока (5–7 строк) на основе последних 3 записей журнала истории срезов и ленты событий.
- `POST /api/v1/assistant/filter-query` — "Отбор словами":
  - Вход: Естественно-языковой запрос (например: *"Не VIP, непереданных >25%, без изменений"*).
  - Выход: Массив `kcr_code` с текстовыми причинами соответствия.
- `POST /api/v1/assistant/chat` — Ответы на вопросы по карточке клиента с обязательными ссылками на даты событий.

## 4. Требования к UI/UX и модулям

1. **Модуль загрузки (Админ):**
   - Дашборд импорта со сводкой (Успешно / Ошибки), виджет скачивания `.xlsx` с ошибками импорта, кнопка «Откатить импорт».
2. **Модуль общей базы:**
   - Цветовая индикация: Зелёный (Уменьшается/Все переданы), Жёлтый (Впервые), Красный (Растёт/Повторно/Просрочено), Серый (Без изменений).
   - Фильтр "Новички с остатком <5%" (бизнес-исключение для обзвона).
3. **Модуль рабочего места оператора:**
   - Раздел «Сегодня нужно» всегда вверху.
   - Очередь свободных клиентов из переданного пула.
   - Модальное окно записи результатов звонка + поля выбора обещанного срока.
4. **Модуль карточки клиента:**
   - Карточка с полной историей взаимодействия: профиль, теги, срезы по кварталам и журнал изменения статуса передачи документов, закрепление и этап, лента событий (включая события прошлых дат).
5. **Модуль ИИ-помощника:**
   - Плашка «Контекст перед звонком» в шапке карточки клиента.
   - Чат-боковая панель для уточняющих вопросов.
