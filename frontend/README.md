# Frontend «Контур КЦР»

Next.js frontend обращается только к Gateway по контракту `../docs/api/public-api.yaml`.

## Запуск

Из каталога `frontend`:

```sh
npm ci
npm run dev
```

По умолчанию браузер отправляет запросы на `/api/v1` текущего сайта. Next.js проксирует их в Gateway по адресу `http://127.0.0.1:8080` при локальном запуске и `http://gateway:8080` в Docker. Внутренний адрес настраивается через `GATEWAY_INTERNAL_URL` перед запуском frontend.

Если браузер должен обращаться к отдельному публичному Gateway, задайте в `.env.local` перед запуском/сборкой:

```dotenv
NEXT_PUBLIC_API_URL=https://gateway.example.local
```

Значение `NEXT_PUBLIC_API_URL` — публичный origin без `/api/v1`. При прямом обращении браузера к отдельному Gateway требуется настройка CORS. При пустом значении используется прокси Next.js на текущем origin. Учётные записи создаёт Identity.

## Docker

Из корня репозитория:

```sh
docker build -t kontur-frontend ./frontend
docker run --rm --name kontur-frontend -p 3000:3000 kontur-frontend
```

Frontend откроется на `http://localhost:3000`. Образ использует Node.js 26.12 из стека проекта, standalone-сборку Next.js и пользователя `node`. В runtime копируются только необходимые зависимости, сервер, статические файлы и `public`; healthcheck проверяет HTTP-ответ frontend.

Внутренний адрес Gateway задаётся при запуске контейнера:

```sh
docker run --rm -p 3000:3000 -e GATEWAY_INTERNAL_URL=http://gateway:8080 --network kontur-kcr_default kontur-frontend
```

При запуске контейнер должен иметь доступ к Gateway по указанному имени и порту. `GATEWAY_INTERNAL_URL` читается сервером при выполнении запросов. В compose она передаётся из `server/.env`, пример указан в `server/.env.example`. После изменения пересоздайте frontend-контейнер. `NEXT_PUBLIC_API_URL` встраивается в клиентский JavaScript при сборке и требует пересборки при изменении. Локальные `.env*`, `node_modules`, `.next` и отчёты покрытия исключены из контекста сборки.

## Интеграция

- Вход: Bearer JWT, сохранение пользователя и срока сессии; выход и HTTP 401 очищают сессию. Роль управляет видимостью UI; права обязан проверять Gateway.
- Реестр: серверный поиск КЦР/ИНН, динамика, длительность, признак, квартал, числовые диапазоны, пагинация. Отсутствующие значения не превращаются в ноль.
- Карточка: профиль, сравнение кварталов, текущие срезы, история наблюдений и событий с пагинацией, происхождение унаследованных полей.
- Взятие и перезакрепление используют `work_quarter`, `expected_assignment_id` и устойчивый `request_id`. Ответ PENDING означает ожидание решения до `expires_at`. Уведомления оператора обновляются каждые 10 секунд, ответственный может отклонить запрос. Действующий WAIT_DEADLINE защищает назначение.
- Звонок и прошлый комментарий записываются оператором с `request_id` и явными `document_quarters`. Форма звонка сохраняет исходный `expected_assignment_id`, отдельно передаёт обещанный срок и `wait_until`, показывает результат `wait_applied`. При потере ответа повтор отправляет те же данные и ID. Изменение ожидания выполняется вместе со звонком.
- Пользователи: чтение и создание по схеме User; отдельного имени и операции изменения роли в контракте нет.
- Импорт отправляет `file` и `import_type` в multipart. Для `SNAPSHOT` обязательны `selected_quarter` и `snapshot_date`. Отчёт по ID пакета опрашивается каждые две секунды до завершения, опрос отменяется при уходе.
- Удаление клиента/квартала и rollback: явное подтверждение, `operation_id` сохраняется для повтора неудачного запроса пока экран открыт. После перезагрузки сначала проверьте результат операции. Последний пакет и глобальное завершение проверяет сервер.

`lib/contracts.d.ts` соответствует схемам публичного YAML; условные требования событий проверяют формы. При изменении контракта обновляйте типы и тесты.

Отчёт об импорте показывает ошибки пакета из `ImportBatch.error_log`. В YAML отсутствуют операции списка импортов, передачи пула, изменения пользователей, редактирования статусов и скачивания XLSX ошибок. «Сегодня нужно» и освобождение клиента исключены ADR-0002; старый `/today` открывает реестр. Функции ИИ отложены ADR-0002 и не подключены.

## Проверка

```sh
npm run lint
npm test -- --runInBand
npm run build
```

Тесты проверяют HTTP-контракт на подменённых ответах Gateway. Для сквозной проверки нужны работающий Gateway, доступные сервисы и тестовые учётные записи ADMIN/OPERATOR. Проверка сборки не доказывает доступность backend.

Для сквозного запуска Gateway должен агрегировать назначение и `work_quarter` в публичную карточку, передавать сервисный токен Operator Work, реализовать публичные маршруты удаления и обеспечить доступность адреса API. В текущем коде Gateway эти части ещё требуют реализации. Публичный контракт событий в описании x-roles допускает ADMIN, но фактический Operator Work разрешает запись только OPERATOR, что учтено в интерфейсе.
