# Актуальные пользовательские сценарии

Редакция 05.11.2026; приоритет — поздние комментарии заказчика и уточнения пользователя. Исходная таблица с комментариями (`use_cases_spreadsheet.xlsx`, лист A11:A14) хранится вне репозитория и в него не входит; она не является актуальным перечнем после этих изменений. Фиксация принятых решений в репозитории — ADR-0002.

| UC | Актуальное поведение |
|---|---|
| 01 | Вход и доступ по роли. |
| 02 | Импорт с явным выбором квартала; квартальные листы; наследование пустых полей с меткой проверки; последний rollback и ручное удаление очищают связанную работу. |
| 03 | Динамика документов по исходным периодам; перенос без потери/двойного счёта; длительная задержка от двух кварталов. |
| 04–06 | Поиск, таблица и карточка с периодами, остатками, меткой проверки и действующим ожиданием оператора. |
| 07 | Формирование/обновление пула; при переходе квартала действующее ожидание сохраняет ответственного до срока. |
| 08 | Исключён. Оператор сам выбирает, кому и когда звонить; очереди «Сегодня нужно» нет. |
| 09 | Любой оператор может перезакрепить клиента, если ещё не действует WAIT_DEADLINE. До даты оператора сохраняется ответственный, включая смену квартала; после даты при остатке клиент вновь доступен. |
| 10–11 | Исключены. Отдельных действий освобождения/административного снятия нет. |
| 12 | Результат звонка, договорённость и срок оператора. WAIT_DEADLINE требует wait_until; перенесённый срок автоматически не продлевается. |
| 13 | Управление пользователями и ролями. |
| 14–19 | Претензии, санкции, письма, вложения и импорт старой истории: глубина реализации ещё требует согласования. |
| 20–23 | Конкретные функции ИИ обсуждаются позже. Размещение определено: облачный API стороннего провайдера. |

Отдельно от отменённых UC-10/11: разрешены административное удаление исходных данных и каскадная очистка операторской работы. Это изменение состава данных, а не операция передачи клиента между сотрудниками.
