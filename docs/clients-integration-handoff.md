# Контракт Clients для разработчиков соседних сервисов

Реализован только Clients. Этот документ помогает подключить Gateway/Identity, Import и Operator Work; он не утверждает, что интеграция уже работает. Проверка межсервисных токенов пока только [предложение](proposals/clients-service-auth.md).

## Ответственность и маршруты

| Потребитель | Внутренний маршрут | Что важно |
|---|---|---|
| Gateway | GET /internal/v1/clients | Фильтры до пагинации; quarter — исходный период документов, не work_quarter |
| Gateway | GET /internal/v1/clients/{kcr_code} | Только клиентские данные; сроки/этап/назначение нужно получить из Operator Work |
| Gateway | GET /internal/v1/clients/{kcr_code}/snapshots/history | limit/offset/total; известный клиент без истории даёт пустой список, неизвестный — 404 |
| Import | POST /internal/v1/import/apply | Нормализованный JSON, не Excel; batch_id — ключ повтора; ошибки отдельных строк не отменяют принятые |
| Координатор Import | POST /internal/v1/import/{batch_id}/rollback | Глобальный последний пакет проверяет координатор; Clients проверяет только локальный порядок |
| Координатор Import | DELETE /internal/v1/clients/{kcr_code} | Полное локальное удаление; другие сервисы обрабатываются координатором |
| Координатор Import | DELETE /internal/v1/clients/{kcr_code}/snapshots/{quarter} | Сохранить остальные кварталы и общую историю операторов |

Откат/удаление используют operation_id и requested_by в JSON-теле, включая DELETE. Публичный Gateway должен сохранить или сформировать этот внутренний конверт. Полный протокол: [clients-recovery-protocol.md](clients-recovery-protocol.md). local_only=true означает только локальное завершение Clients.

## Что требуется от Gateway

1. Проверять пользовательский доступ до вызова Clients. Клиентский бизнес-ключ — строка kcr_code; ИНН не уникален. Нули в идентификаторах сохраняются.
2. Передавать числовые фильтры за выбранный quarter. Без него Clients берёт календарный квартал Europe/Moscow; для одинакового отображения в интерфейсе предпочтительно передавать выбранный период явно.
3. Собирать публичную карточку из Clients и Operator Work. Clients не хранит назначения, этапы и сроки и отклоняет неподдерживаемые query-параметры.
4. Согласовать пересечение клиентских и операторских фильтров до total/пагинации. Нельзя получить одну страницу Clients, затем скрыть из неё клиентов других операторов и объявить total корректным.
5. Не показывать success глобального удаления/отката, пока координатор не завершил всех участников. Не принимать requested_by из непроверенного публичного тела как подтверждение автора.

## Ошибки и повтор

400 — неверные параметры/конверт; 404 — неизвестный клиент или пакет; 409 — конфликт batch_id/operation_id, не последний пакет, неизвестный старый порядок или уже отменённый batch_id; 503 — повторить позже. Значения внутренних ошибок БД не возвращаются. Ошибки строк apply входят в успешный HTTP-ответ с rejected_rows/errors.

После потери ответа повторяется тот же ID и payload. Для новой загрузки или нового административного действия создаётся новый ID. Решение о повторах глобальной операции сохраняет координатор; Clients не запускает вызовы остальных сервисов самостоятельно.

## Проверки перед общим стендом

Миграции применяет отдельное задание до HTTP. /health/live проверяет процесс, /health/ready — доступность БД и ожидаемую ревизию. Docker Compose использует только localhost и демонстрационные локальные пароли. Секреты стенда и авторизация ещё не настроены.

GitHub Actions подготовлен для линтера, PostgreSQL-тестов и build/start контейнера. Локальный HTTP-сценарий Clients проверяет импорт → чтение → удаление квартала → откат → повтор команды; он не заменяет испытание с настоящими Gateway, Import и Operator Work.
