# Контракт Import Worker и Operator Work

**Статус:** координатор утверждён в [ADR-0007](../adr/0007-import-worker-coordinator.md). Маршруты и форматы ниже соответствуют работающему внутреннему API Operator Work. Порядок интеграции и условия восстановления предназначены для реализации в Import Worker. Сквозное подключение будет проверено при готовности сервисов.

## Ответственность и доступ

| Участник | Ответственность |
|---|---|
| Import Worker | Ведёт статус пакета и последовательность шагов, проверяет допустимость отката, получает результаты Clients, фиксирует точные цели очистки, повторяет незавершённые запросы. |
| Clients | Хранит наблюдения и вычисляет общий актуальный остаток по уникальным исходным кварталам. Подтверждает применение и откат своих данных. |
| Operator Work | Создаёт неопубликованные циклы, сохраняет ожидание при переходе квартала, выполняет локальную очистку и явно указанное восстановление. Подтверждает только локальный шаг. |

Import Worker вызывает Operator Work во внутренней сети по TLS или за защищённой границей внутреннего сервиса. Текущий API проверяет `Authorization: Bearer <service-token>`, `X-User-Id: <UUID администратора>` и `X-User-Role: ADMIN`. Инициатор берётся из проверенного контекста задачи Import Worker. В повторах используется тот же инициатор. Токены хранятся в настройках сервиса и не включаются в журналы или тело команды. Окончательная выдача сервисных полномочий согласуется при подключении.

## Применение среза

1. Import Worker сохраняет UUID пакета, выбранный квартал и инициатора. Он применяет данные в Clients и дожидается подтверждения. Для последующих шагов используются только принятые данные; отклонённая строка не создаёт цикл.
2. Для затронутых клиентов Import Worker получает **общий актуальный остаток** из Clients, дедуплицирует записи по коду КЦР и сохраняет неизменяемое тело следующего запроса. Если нужно будет восстановить прежнюю работу, координатор до изменения циклов фиксирует её состояние или получает проверяемую ссылку на сохранённое состояние. Отсутствие подтверждённого остатка нельзя подставлять как ноль. Если подходящих клиентов нет, шага обновления циклов нет.
3. Import Worker передаёт нормализованный срез. `work_quarter` равен выбранному администратором кварталу. Реестр без наблюдений сам по себе не является срезом для этого вызова.

```http
PUT /internal/v1/cycles/apply-snapshot?work_quarter=2026_Q4
Content-Type: application/json
```

```json
{
  "batch_id": "73e34430-2f72-4001-9bed-0d11c70dd272",
  "clients": [
    {"kcr_code": "AAA00412", "outstanding_documents": 3},
    {"kcr_code": "AAA02210", "outstanding_documents": 0}
  ]
}
```

`204 No Content` означает, что Operator Work применил пакет или уже применял эти данные с тем же ID. Положительный остаток может создать новый **неопубликованный** цикл. Ноль не создаёт цикл, повтор и старый квартал не сбрасывают работу. При смене квартала незавершённое ожидание сохраняет оператора и дату. Публикация выполняется администратором отдельно. Import Worker выставляет итоговый `COMPLETED` после подтверждений обязательных шагов, включая Operator Work, если вызов требовался.

### Большие пакеты

В одном запросе от 1 до 1000 уникальных клиентов. Для большой выгрузки действует [ADR-0009](../adr/0009-snapshot-delivery-parts.md). Import Worker дедуплицирует весь список, фиксирует неизменяемый набор частей и отправляет каждую через тот же маршрут, добавляя в тело поле `delivery`:

```json
{
  "delivery_id": "c14fb056-ad41-45e6-ac57-0eeef939bd21",
  "part_number": 1,
  "part_count": 2
}
```

Исходный `batch_id` и выбранный квартал общие для всех частей. Части нумеруются с 1, номер и ID доставки уникальны в пределах пакета. Допустимо от 2 до 1000 частей. Повтор отправляет тот же набор клиентов для того же номера и ID. Сервис хранит подтверждение каждой части в той же транзакции, что и созданные циклы. Порядок прихода частей одного пакета не влияет на корректность. Результат `204` подтверждает только текущую часть. Import Worker завершает пакет после подтверждений всех частей и других обязательных шагов. При сбое возобновляются части без подтверждения. Циклы сохраняют исходный `batch_id`, даже если созданы разными частями. Небольшой пакет можно отправить одним запросом без `delivery`; смена способа доставки под тем же ID запрещена.

## Откат и выборочная очистка

1. Import Worker проверяет, что отменяется последний применённый, ещё не отменённый пакет. Он готовит и сохраняет план по каждому клиенту: какие циклы и события действительно связаны с отменяемыми данными, нужно ли восстановление, какие данные должен восстановить Clients. Для удаления исходного квартала указывается исходный период документов, для полного удаления используется область `CLIENT`.
2. ID циклов доступны через `GET /internal/v1/clients/{kcr_code}/cycles`, а ID событий — в пагинированном `GET /internal/v1/clients/{kcr_code}/events`. Лента также возвращает явно сохранённые document_quarters. Пустой список и несколько кварталов обозначают общую или неподтверждённую историю. Привязка к исходному кварталу не доказывает принадлежность конкретному пакету. Нельзя выбирать цели по совпадению номера исходного квартала и квартала обзвона.
3. Для отката сначала подтверждается восстановление в Clients, затем Import Worker отправляет отдельный запрос очистки Operator Work для каждого клиента, которому она нужна. Для каждой команды заранее сохраняется отдельный `operation_id`. Если промежуточный шаг завершился, повтор начинается с шага без подтверждения. До получения всех подтверждений операция остаётся незавершённой; следующий конфликтующий пакет не применяется.

```http
POST /internal/v1/data-cleanup
Content-Type: application/json
```

```json
{
  "operation_id": "37f8419e-f316-43a2-9e28-e14713891dcc",
  "kcr_code": "AAA00412",
  "scope": "BATCH",
  "batch_id": "73e34430-2f72-4001-9bed-0d11c70dd272",
  "cycle_ids": ["2919a38a-a5fb-47cc-891a-6ac4990e5ca6"],
  "event_ids": ["77d6c934-4895-4c40-9f98-9db33969b8a0"],
  "restore": {
    "cycle_id": "592a9bc1-37c2-4219-9573-227ed3003069",
    "published": true,
    "stage": "WAIT_DEADLINE",
    "operator_id": "07ca0036-5a9d-4399-89df-e84d92293d46",
    "wait_until": "2026-12-14"
  }
}
```

| Область | Поля и правила |
|---|---|
| `CLIENT` | Только `operation_id`, `kcr_code`, `scope`. Удаляется вся локальная работа клиента. |
| `QUARTER` | `quarter` для контекста и непустой набор целей в `cycle_ids` или `event_ids`. Другой текущий цикл не выбирается автоматически. |
| `BATCH` | `batch_id` и непустой набор целей. Целиком можно удалить циклы, созданные указанным пакетом. Если удаляется текущий цикл, но остаются другие, нужно передать `restore` с ID оставшегося цикла и явным состоянием. Для `WAIT_DEADLINE` обязательны оператор и дата. |

Для выборочной очистки разрешено до 100 уникальных циклов и до 5000 уникальных событий на клиента. Для удаления цикла нужно явно перечислить все его события. Пользовательские события с пустой или множественной привязкой сохраняются при выборочной очистке. При QUARTER пользовательское событие можно удалить только при единственной привязке к указанному кварталу. Системное событие можно удалить вместе с выбранным циклом. При откате, который не удаляет текущий цикл, состояние оставшейся работы не меняется. `200` и `status: COMPLETED` подтверждают локальную очистку. Внешний статус отката или удаления устанавливается после подтверждений всех затронутых участников.

## Повторы, конфликты и сверка

| Результат | Действие Import Worker |
|---|---|
| Таймаут, обрыв связи, `408`, `429` или `5xx` | Результат может быть неизвестен. Повторить с тем же ключом, кварталом, телом и инициатором. Использовать задержку с увеличением интервала и учитывать `Retry-After`, если он есть. |
| `204` при применении пакета или части, `200 COMPLETED` при очистке | Сохранить подтверждение шага. Уже подтверждённый шаг повторять не нужно. |
| `409 SNAPSHOT_ID_CONFLICT`, `SNAPSHOT_PART_CONFLICT` или `OPERATION_ID_CONFLICT` | Остановить шаг и сверить сохранённую команду с использованным ID. Новый ID не выдаётся автоматически. |
| `409 CLEANUP_TARGET_CONFLICT`, `RESTORE_REQUIRED` или `INVALID_RESTORE` | Остановить очистку, заново проверить цели и состояние. Например, после подготовки плана оператор мог записать звонок. Изменённый план утверждается координатором как новая команда с новым ID. Старый ответ или неоднозначный сетевой исход сначала сверяются. |
| `401`, `403`, `422` | Исправить конфигурацию, полномочия или команду до повтора. |

Журнал координатора хранит идентификаторы, инициатора, неизменяемые команды и подтверждения шагов. Подтверждение не заменяется статусом всего процесса. Если запись в Operator Work успела завершиться, а ответ потерялся, повтор применяет правила идемпотентности. Импорт и откат не используют общую транзакцию между БД. Нельзя автоматически запускать компенсацию, пока результат предыдущего вызова неизвестен.

## Что проверить при подключении

- Потеря ответа после применения, перезапуск Import Worker и повтор той же команды. Цикл создаётся один раз, назначения и сроки сохраняются.
- Ошибка Operator Work после успешной записи в Clients. Импорт не получает итоговый успех, а после восстановления продолжает незавершённый шаг.
- Запоздавший срез старого квартала. Текущий цикл не меняется.
- Откат после начала работы оператора. Удаляются только согласованные записи, сохраняются общая история и другие циклы, восстанавливается явно указанный ответственный и срок.
- Срыв очистки одного клиента после подтверждения других. Координатор повторяет только незавершённый шаг и не завершает общий откат раньше времени.

Import Worker может сохранить состояние до изменения через `GET /internal/v1/clients/{kcr_code}/cycles`. Маршрут возвращает и исторические, и неопубликованные циклы с этапом, ответственным, сроком и источником ожидания. Для `restore` используются `cycle_id`, `published = (published_at != null)`, `stage`, `operator_id = assigned_operator_id`, `wait_until` и `wait_source_work_quarter`. Пустой этап или этап вне поддерживаемых значений требует сверки, а не подстановки.

Источник привязки утверждён в [ADR-0008](../adr/0008-event-document-quarters.md). При откате Import Worker сверяет привязку с данными Clients. Для сквозной реализации Import Worker должен сохранять план частей и их подтверждения в своём журнале.
