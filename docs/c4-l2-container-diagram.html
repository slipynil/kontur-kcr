Сервис обзвона клиентов: контейнеры

Тип: диаграмма контейнеров C4 (L2). Охват: одна программная система «Сервис обзвона клиентов». Внутри границы — четыре слоя: Presentation → Business → Persistence → Database. Вне границы — пользователи и внешние инструменты: LLM и MCP Server. Внутреннее устройство сервисов (компоненты, L3) не показано.

Чтение вслух

  1. Контейнеры внутри границы системы организованы по слоям сверху вниз: Presentation (Web App, nginx) → Business (сервисы с бизнес-логикой) → Persistence (RabbitMQ) → Database (PostgreSQL, у каждого сервиса своя БД).
  2. Оператор и администратор работают через Web App. Все запросы идут через nginx в Gateway / Identity: он проверяет токен и роль и направляет запрос в нужный сервис.
  3. Администратор загружает Excel в Import API. Import API кладёт задачу в RabbitMQ (слой Persistence) и сразу отвечает. Import Worker забирает задачу, разбирает файл и загружает клиентов и срезы в Clients Service.
  4. Clients Service хранит реестр в своей БД и отвечает на поиск по КЦР/ИНН, карточку, журнал изменений и динамику.
  5. Operator Work Service ведёт процесс обзвона в своей БД. Данные клиента он запрашивает у Clients Service.
  6. Пользователь пишет в чат: Assistant Service отправляет промпт во внешнюю LLM, а действия выполняет через MCP Server — внешний инструмент, как LLM, вне границы системы. MCP Server вызывает только Operator Work Service.
