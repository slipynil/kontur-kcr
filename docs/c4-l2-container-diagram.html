Сервис обзвона клиентов: контейнеры

Тип: диаграмма контейнеров C4 (L2). Охват: одна программная система «Сервис обзвона клиентов» — все её развёртываемые контейнеры и хранилища, пользователи (оператор, администратор) и внешняя LLM. Внутреннее устройство сервисов (компоненты, L3) не показано.

100%

По умолчанию схема вписана в ширину окна. При увеличении её можно прокручивать внутри рамки.

Легенда

  • Пользователь системы (Person)
  • Фронтенд (SPA в браузере)
  • Инфраструктура без бизнес-логики
  • Сервис на Go
  • Сервис на Python
  • Цилиндр — база данных (PostgreSQL), принадлежит одному сервису
  • Двойная рамка — брокер сообщений
  • Серый — внешняя система вне нашего контроля
  • Пунктирная рамка — граница системы
  • Синхронный вызов. Стрелка идёт от инициатора, в скобках — протокол
  • Асинхронное взаимодействие через очередь

Внутри блока: жирным — название, в скобках — тип и технология, курсивом — назначение в одном предложении.

Чтение вслух

  1. Оператор и администратор работают через Web App. Все запросы идут через nginx в Gateway / Identity: он проверяет токен и роль и направляет запрос в нужный сервис.
  2. Администратор загружает Excel в Import API. Import API кладёт задачу в RabbitMQ и сразу отвечает. Import Worker забирает задачу, разбирает файл и загружает клиентов и срезы в Clients Service.
  3. Clients Service хранит реестр в своей БД и отвечает на поиск по КЦР/ИНН, карточку и динамику.
  4. Operator Work Service ведёт процесс обзвона в своей БД. Данные клиента он запрашивает у Clients Service.
  5. Пользователь пишет в чат: Assistant Service отправляет промпт во внешнюю LLM, а действия выполняет через MCP Server, который вызывает только Operator Work Service.
