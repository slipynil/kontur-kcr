## Дополнительная проверка настоящего HTTP 08.11.2026

Добавлен `services/clients/scripts/check_http.py`, работающий через urllib стандартной библиотеки. Он не импортирует FastAPI-приложение и не использует TestClient. Локально выполнен против отдельного процесса Uvicorn и временной PostgreSQL БД:

- режим closed: все семь бизнес-маршрутов отвечают 404; OpenAPI не содержит этих маршрутов; live/ready успешны;
- режим business: импорт реестра и двух кварталов, исправление и повтор batch_id, карточка, числовой фильтр и история;
- удаление Q1 и откат последнего пакета: восстановлены прежние остатки Q1/Q2 и история;
- повтор старой команды удаления: восстановленные данные сохранились;
- другой клиент не затронут, синтетические клиенты удалены последовательными откатами созданных пакетов;
- после выполнения HTTP-процессы остановлены и временная БД удалена.

Проверка использует только синтетические данные и loopback. Режим business предназначен для отдельного тестового сервиса, в котором включены три CLIENTS_ENABLE_* флага. Это не механизм авторизации и не инструкция открыть общий стенд.

## Что изменено в следующем запуске CI

Workflow теперь использует общий скрипт closed, затем включает бизнес-маршруты только в своём временном Compose-проекте через `compose.check.yaml` и запускает business через HTTP-порт контейнера. Обычный compose.yaml сохраняет закрытые маршруты.

**Расширенный сценарий контейнера пока не запущен в GitHub Actions.** Локально Docker отсутствует; локальный успех относится к реальному HTTP-процессу Uvicorn, а подтверждённый контейнерный успех — к коммиту 433aa64. После следующего push нужно проверить оба задания нового запуска.
