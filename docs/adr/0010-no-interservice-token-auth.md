# 0010. Отмена межсервисной токенной авторизации

## Status

Accepted — решение пользователя от 15.11.2026.

## Decision

Проверка сервисного Bearer-токена между микросервисами не выполняется. Аутентификация и авторизация — зона ответственности Gateway / Identity: он проверяет JWT пользователя и роль, после чего передаёт личность и роль в заголовках `X-User-Id` и `X-User-Role`. Внутренние сервисы доверяют этим заголовкам безусловно и дополнительной сервисной авторизации не вводят.

Из Operator Work удаляются переменная `OPERATOR_WORK_SERVICE_TOKEN` и проверка `Authorization: Bearer` во внутренних эндпоинтах. Тот же принцип применяется к остальным вызовам внутреннего контура (Import Worker, Clients).

## Consequences

Доверенная граница системы — Gateway; внутренний контур изолируется на уровне сети (внутренние порты недоступны снаружи). Присланные клиентом заголовки `X-User-Id` и `X-User-Role` Gateway затирает и проставляет сам. Проверка ролей внутри сервисов (`ADMIN` / `OPERATOR`) сохраняется. Публичный JWT в `docs/api/public-api.yaml` не меняется. ADR-0004 остаётся в силе: Gateway передаёт проверенный ID пользователя и роль.
