# 0005. Чтение Clients и сравнение квартальных остатков

## Status

Accepted — уточнения пользователя от 07.11.2026 в текущем чате.

## Context

После этапа применения пакетов реализуется чтение реестра. Пользователь изменил прежнее правило динамики внутри одного квартала: сравниваются остатки разных исходных кварталов. Этот пункт заменяет соответствующие положения ADR-0003 и прежних спецификаций; старые ADR сохраняются.

## Decision

1. Динамика сравнивает актуальный остаток исходного квартала с актуальным остатком предшествующего исходного квартала. По умолчанию берутся текущий календарный квартал Europe/Moscow и предыдущий; quarter выбирает иной текущий период сравнения. Если одного из двух периодов нет, dynamics=null. Ноль является известным значением, отсутствие не подменяется нулём.
2. При известной паре: текущий ноль — ALL_SUBMITTED; меньше предыдущего — REDUCING; больше — GROWING; равен — NO_CHANGE. Это сравнение разных комплектов документов, а не измерение передачи одного комплекта. Ответ показывает оба квартала и оба остатка, на которых основан показатель. История наблюдений внутри каждого периода сохраняется отдельно.
3. Поиск по КЦР/ИНН — буквальное вхождение без учёта регистра; выбранные теги применяются одновременно (AND), сортировка — стабильная по КЦР. Параметры динамики/длительности применяются до подсчёта total и пагинации. Фильтр dynamics без quarter использует календарную пару по умолчанию.
4. quarter задаёт только пару для динамики, не скрывает другие исходные периоды и не ограничивает общий остаток. latest_snapshot — состояние самого позднего исходного квартала клиента. В карточке список актуальных срезов упорядочен по исходному кварталу; snapshots_limit не влияет на остаток или категорию.
5. Длительность определяется загруженными наблюдениями, без автоматического старения от календарной даты. Непереданные документы Q1, сохраняющиеся в наблюдении Q2, — LONG_DELAY_2Q. После полного обнуления начинается новый период, прежняя длительность на него не переносится. Пропуск периода/строки не обнуляет остаток.
6. Строки разных исходных кварталов одного пакета на одну дату составляют одно наблюдение клиента. Остатки восстанавливаются по хронологии (дата, порядок исправления), затем вычисляются эпизоды между полными обнулениями. Поэтому порядок строк не создаёт фиктивный повтор или промежуточный ноль. Если пакет содержит разные даты наблюдений, каждая дата обрабатывается отдельно.
7. История: limit/offset/total, свежие даты и исправления первыми. Внутри одного HTTP-запроса чтение выполняется в согласованной read-only транзакции PostgreSQL. Между отдельными страницами при новом импорте снимок не фиксируется; для статической выгрузки понадобится отдельный контракт.
8. HTTP-чтение выключено по умолчанию до согласования межсервисной авторизации; CLIENTS_ENABLE_REGISTRY_READ включает его только для изолированной разработки. Не поддерживаемые фильтры операторов не игнорируются. Gateway должен согласовать объединение выборок до пагинации, когда будет готов Operator Work.

## Consequences

Обновляются бизнес-ТЗ, спецификации и контракты. Расчёты выполняются в PostgreSQL до LIMIT/OFFSET без загрузки всей истории в Python и без сетевых запросов к Operator Work. Схема Clients DB не меняется; новые миграции этому этапу не требуются. Цветовая индикация при нескольких состояниях, глобальная авторизация и операторские фильтры остаются вне этапа.
