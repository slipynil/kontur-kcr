# 0004. Перезакрепление по запросу с правом отказа

## Status

Accepted — решения пользователя от 09.11.2026.

## Decision

- Импорт сам по себе не публикует пул. Операторы работают с клиентами, переданными администратором.
- Взятие свободного клиента завершает назначение сразу. Два разных оператора с одной версией свободной карточки не могут оба успешно выполнить взятие. Для проверки версии используется ID активного назначения или null.
- При запросе на занятого клиента действующий ответственный получает уведомление внутри приложения. Ответственный может отказать до истечения одного часа с момента создания запроса. При отказе закрепление сохраняется. Без отказа по истечении часа выполняется автоматическая передача.
- Действующий WAIT_DEADLINE сохраняет приоритет. При автоматической передаче повторно проверяются актуальность цикла, исходного назначения и защита по сроку. Устаревший запрос отменяется.
- На клиента в текущем цикле допускается один ожидающий запрос. Повтор отправки с тем же ID запроса возвращает сохранённый результат. Отказ, автоматическая передача и назначение сериализуются по клиенту.

## Consequences

Правило заменяет немедленное перезакрепление из ранних формулировок. Operator Work владеет запросами и уведомлениями. Gateway передаёт проверенный ID пользователя и его роль. Уведомление хранится в БД как запись запроса и доступно участникам через API.
