# 0004. Локальное применение пакетов Clients

## Status

Accepted — пользователь принял предложения в чате 07.11.2026.

## Context

Нужно реализовать приём нормализованных данных, не подменяя глобальную координацию Import. Межсервисная авторизация с Gateway ещё не согласована.

## Decision

1. batch_id — ключ идемпотентности. Повтор идентичного запроса возвращает сохранённый результат; другой payload с тем же ID — 409 IMPORT_PAYLOAD_CONFLICT. Хэш считается по каноническому JSON конверта, включая порядок строк.
2. Корректные строки сохраняются, ошибочные возвращаются в отчёте по индексу (с единицы), коду и полю без исходных персональных значений. Каждая строка обрабатывается в savepoint. Некорректный конверт отклоняется целиком.
3. Данные, локальный результат и undo фиксируются одной транзакцией Clients DB. Import остаётся координатором; ответ Clients не означает завершения пакета всей системы.
4. Реализация сериализует локальное применение пакетов advisory-lock PostgreSQL. Это простой первый вариант для небольших пакетов; распределённого lock и записи в чужие БД нет. Таймаут/системная ошибка откатывает локальную транзакцию целиком, допускается повтор с тем же batch_id.
5. Для одной даты исправления имеют монотонный observation_order в истории. Исторический срез не перезаписывает актуальное состояние. Наследование остатка берёт последнее наблюдение не позже даты среза и только того же исходного квартала. total фиксируется первым применённым импортом исходного периода.
6. Происхождение актуальных полей профиля хранится в field_sources; более раннее значение не заменяет более свежее. Отсутствующий в частичном профиле ключ не меняет профиль, переданная пустота наследует значение с предупреждением. Имена непроверенных полей срезов включают исходный квартал.
7. Дубликат (КЦР, исходный квартал) внутри SNAPSHOT-пакета или КЦР внутри REGISTRY-пакета — ошибка повторной строки; разные исходные кварталы разрешены. Категории клиента в дальнейшем рассчитываются по наблюдениям пакета как единому срезу, а не порядку его строк.
8. Новые таблицы clients_import_operations и clients_import_undo принадлежат Clients. Undo хранит предыдущее состояние профиля/тегов/срезов/происхождения и ID новых наблюдений, но не копирует весь журнал истории. Применение и будущие rollback/delete должны использовать один механизм сериализации. Очистка undo при ручном удалении будет частью отдельного этапа; HTTP удаления пока отсутствует.
9. Изменяющий HTTP-маршрут по умолчанию выключен. Его включение — только явная локальная настройка для изолированной разработки; это не согласованная авторизация и не основание открыть маршрут на общем стенде. Health endpoints работают независимо.

## Consequences

Не реализуются глобальный выбор последнего rollback, Operator Work, парсинг Excel и конечная межсервисная авторизация. Идентичность файла между разными batch_id обеспечивает Import; Clients различает новые пакеты и повтор доставки одного пакета. Дополнительные ограничения размера и аутентификация должны быть согласованы перед общим стендом.
