# 0022. ИИ-помощник ai-assistent на TypeScript со встроенным MCP-сервером

## Status

Accepted — решение пользователя от 27.11.2026: сервис `ai-assistent` на TypeScript заменяет планировавшийся Python Assistant Service, MCP-сервер встраивается в сервис, провайдер и модель согласуются отдельно, MVP содержит только чтение.

## Context

`docs/requirements/ТЗ.md` предлагает три функции ИИ-помощника: контекст перед звонком, ответы о состоянии и динамике клиента со ссылками на историю и подбор приоритетного списка на обзвон словами. Четвёртое требование — честность: помощник отвечает только по данным сервиса и не меняет этапы, статусы и обзвон без подтверждения сотрудника.

Пока функции не были согласованы, `spec.md` §3.4 и `docs/api/internal/assistant-service.yaml` хранили операции `summary`, `filter-query` и `chat` как предложения со статусом «функции не согласованы». ADR-0001 закреплял Assistant Service за Python и выносил MCP Server за границу системы как внешний инструмент, вызывающий Operator Work Service. Сам сервис не реализован.

Для ИИ-функций выбраны Vercel AI SDK (TypeScript) и MCP TypeScript SDK v2 — стабильная ветка спеки MCP 2026-07-28 с запросом на ввод (Elicitation / input required), Skills, Tasks и MCP Apps.

Ограничения: облачный API стороннего провайдера без публикации выгрузок (AGENTS.md); доверенная граница — Gateway (ADR-0010); в операторском контуре доступны только клиенты с текущим опубликованным циклом (ADR-0014, ADR-0018).

## Considered Options

1. **Оставить Assistant Service на Python по ADR-0001.** Выбранный движок Vercel AI SDK — библиотека TypeScript. Пришлось бы брать другой агентный фреймворк и Python-реализацию MCP и поддерживать второй набор примитивов.
2. **Сервис на TypeScript с отдельным MCP-сервером.** MCP-сервер становится отдельным deployable и сетевым переходом. Других потребителей, кроме ассистента, сейчас нет.
3. **Сервис на TypeScript со встроенным MCP-сервером.** Один deployable; граница протокола MCP сохраняется внутри.

## Decision

Выбран вариант 3.

### Сервис и стек

- `ai-assistent` — отдельный сервис на TypeScript (Node.js 26.12), каталог `services/ai-assistent`. Отвечает за ИИ-помощника по данным сервиса и заменяет Python Assistant Service из ADR-0001.
- Движок — Vercel AI SDK: агент с циклом вызова инструментов, инструменты со схемами Zod, структурированный вывод, поток ответа по протоколу UI message stream.
- Собственной БД нет. Сервис не хранит данные клиентов и историю диалогов: каждый запрос читает актуальные данные внутренних сервисов. Удалённые данные не попадают в контекст и не кэшируются.
- Провайдер и модель облачного ИИ задаются конфигурацией и согласуются отдельно.

### Устройство

- Внутри сервиса два компонента: агент и встроенный MCP-сервер. Агент — MCP-клиент; он обращается к серверу по Streamable HTTP на loopback. MCP-сервер наружу не публикуется.
- Протокол между агентом и сервером — MCP 2026-07-28. Клиентская библиотека выбирается при реализации; обязательны инструменты, запрос на ввод и Skills.
- Инструменты MCP — только чтение: `get_call_context`, `get_client_card`, `get_snapshot_history`, `get_history_events`, `query_clients`. Они вызывают внутренние API Clients, Operator Work и Client History и передают заголовки `X-User-Id` и `X-User-Role`, полученные от Gateway (ADR-0010).
- Граница MCP сохраняет смысл ADR-0001: при появлении других хостов (Claude Code, Cursor) сервер выносится в отдельный deployable без изменения инструментов.

### Функции MVP — только чтение

| Функция | Операция | Роли | Инструменты |
|---|---|---|---|
| Контекст перед звонком | `GET /api/v1/assistant/summary/{kcr_code}` | `ADMIN`, `OPERATOR` | `get_call_context` |
| Вопросы о состоянии и динамике за период | `POST /api/v1/assistant/chat/{kcr_code}` | `ADMIN`, `OPERATOR` | `get_client_card`, `get_snapshot_history`, `get_history_events` |
| Приоритетный список на обзвон | `POST /api/v1/assistant/filter-query` | `ADMIN` | `query_clients` |

- Чат закреплён за клиентом из маршрута. Gateway проверяет видимость оператора так же, как для карточки (ADR-0014, ADR-0018). Код клиента и идентичность пользователя сервис передаёт в каждый вызов инструмента; модель их не выбирает.
- Критерии отбора ассистент переводит в параметры фильтра реестра `GET /api/v1/clients`; отбор выполняет Clients Service, а не модель. Условия без фильтра в реестре (исключение признака, отсутствие ответственного) применяет код сервиса по данным Clients и Operator Work. Применённые и неприменимые условия возвращаются с результатом.
- Модель формулирует причину попадания клиента в список только по фактам отобранных записей.

### Честность и контроль

- Ответы основаны только на фактах инструментов. Если данных для ответа нет, ассистент прямо сообщает об этом.
- Ответ на вопрос по клиенту сопровождается ссылками на записи хроники и наблюдений, на которых он основан.
- Терминологический бан `spec.md` §1.2 действует для текстов ассистента: в инструкциях и Skills используются только «непереданные документы» и «неотправленные документы».
- Изменяющих действий нет. Инструменты MCP объявлены только читающими, сервис не вызывает пишущие API. Публикация списка на обзвон остаётся действием администратора через `PUT /api/v1/pool/publication`. Подтверждения (`toolApproval`) и изменяющие действия вводятся после отдельного согласования.
- В облачный провайдер передаются данные клиента из запроса и результат отбора. Полные выгрузки не передаются и не публикуются.

### Новые возможности MCP

- **Запрос на ввод (Elicitation / input required).** Если период или критерии не определены, инструмент возвращает запрос на ввод вместо результата. Агент приостанавливается, пользователь отвечает в интерфейсе, сервис повторяет вызов с ответом. Состояние между шагами переносит диалог; сервер соединение не удерживает.
- **Skills.** Доменные инструкции лежат в репозитории сервиса как `SKILL.md`: терминология, правила кварталов и динамики, шаблон выжимки перед звонком, правила отбора. Встроенный MCP-сервер отдаёт их через `skills/list` и `resources/read`.
- **Tasks и MCP Apps** в MVP не входят. Tasks рассчитан на длительный отбор по всей базе, MCP Apps — на интерактивные представления; список и динамику пока рисует фронтенд.

## Consequences

**Плюсы:**

1. Один сервис и один deployable. Недоступность ассистента не влияет на работу операторов с реестром и карточкой.
2. Ответы проверяемы: факты приходят из инструментов со ссылками, отбор определяется фильтрами реестра.
3. Данные не дублируются: нет БД и кэшей, удаление данных сразу исключает их из контекста.
4. Граница MCP позволяет подключать инструменты к другим хостам и вынести сервер без переписывания агента.
5. Провайдер и модель заменяются конфигурацией.

**Минусы:**

1. TypeScript — третий стек после Python и Go: свои Dockerfile, линтер и тесты. Воркфлоу `assistant-service-pr-checks` рассчитано на Python и требует обновления владельцем CI.
2. Публичный контракт чата зависит от протокола UI message stream AI SDK. Замена движка потребует адаптера протокола.
3. Ответ агента не укладывается в таймауты HTTP-сервера Gateway без отдельной настройки таймаута маршрута.
4. Операции ассистента зависят от облачного провайдера и трёх внутренних сервисов; при их недоступности они отвечают ошибкой `ASSISTANT_UNAVAILABLE`.
5. Перевод текста в критерии зависит от модели. Риск снижают возвращаемые применённые и неприменимые условия.

ADR-0001 изменяется в части стека и размещения MCP: сервис `ai-assistent` на TypeScript со встроенным MCP-сервером вместо Python-сервиса с внешним MCP Server. `spec.md` §1.1, §3.4, §4, §5, §6 и §7 обновляются, диаграмма C4 L2 обновляется. Контракт — [OpenAPI](../api/internal/assistant-service.yaml), публичные операции — [публичный API](../api/public-api.yaml).
