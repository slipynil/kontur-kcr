# 0021. История ошибок импорта в Errors History

## Status

Accepted — согласовано пользователем 23.11.2026.

## Context

Import DB хранит ошибки пакетов в `import_errors`. Отсюда Import API формирует отчёт и `errors.xlsx`. Для чтения ошибок по коду КЦР требуется независимая история, в которую входят также ошибки без КЦР и ошибки книги или листа целиком.

## Decision

- Errors History — отдельный Python-сервис со своей PostgreSQL DB. Он хранит только строки `import_errors` пакетов `REGISTRY` и `SNAPSHOT`. Единственный источник — Import Worker, включая записанные им отказы Clients Service. Граница доверия соответствует [ADR-0010](0010-no-interservice-token-auth.md). При создании исходящего события Worker подтверждает существование пакета в Import DB.
- `import_errors` остаётся источником отчёта. При добавлении ошибки Worker в той же транзакции создаёт запись в своей таблице outbox. Отдельный отправитель передаёт ошибки по HTTP после коммита, с ограниченным backoff при временном сбое. Доставка истории выполняется независимо от итогового статуса импорта. HTTP 409 фиксируется для диагностики с сохранением исходящей записи.
- Приём всей отправленной порции атомарен. Повтор по `source_error_id` с теми же данными безопасен. Изменение данных под тем же ID возвращает HTTP 409. КЦР хранится как текст с исходными ведущими нулями. Название листа, номер строки и причина сохраняются как в источнике. Между базами используются логические ссылки.
- Время новой ошибки фиксируется при её записи в Import DB. Для прежних строк без даты `recorded_at` остаётся `null`. При чтении они идут после датированных. Совпадающие даты и записи без даты упорядочиваются по убыванию `source_error_id`.
- Перенос читает Import DB и повторно использует обычный bulk API. Политика хранения и очистки согласуется отдельно. До её согласования история сохраняется при откате пакета и полном удалении клиента.
- Через Gateway ошибки по КЦР может читать только `ADMIN`. Пакетное чтение и запись доступны во внутреннем API. Локальный порт 8006 привязан к loopback. Подключение к общему стеку и публикация образа выполняются отдельным этапом.

Модель данных — [DDL](../db/ddl/errors_history.sql). Контракт — [OpenAPI](../api/internal/errors-history.yaml).
