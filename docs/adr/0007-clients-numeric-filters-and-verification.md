# 0007. Числовые фильтры выбранного квартала

## Status

Accepted — пользователь выбрал фильтры только по выбранному кварталу 07.11.2026.

## Context

ТЗ требует отбора по количеству и проценту непереданных документов. Суммарный остаток и динамика уже существуют. Пользователь подтвердил, что числовой отбор относится к выбранному исходному кварталу, а схему межсервисных токенов пока попросил оформить только предложением.

## Decision

1. min_unsubmitted_documents/max_unsubmitted_documents задают включительный диапазон числа непереданных документов выбранного quarter. min_unsubmitted_percent/max_unsubmitted_percent — включительный диапазон процентов от total_documents этого же периода. Без quarter используется текущий календарный квартал по Москве.
2. Если периода нет, числовая выборка исключает клиента; отсутствие не считается нулём. Без числовых фильтров клиент остаётся видимым, как в ADR-0005. При total_documents=0 процент не определён (null), процентный фильтр исключает такую запись. Количественный отбор остаётся возможным. Порог процента задаётся в шкале 0–100; процент данных не ограничивается искусственно 100 при несогласованных исходных счётчиках.
3. quarter_summary показывает квартал, total_documents, unsubmitted_documents и unsubmitted_percent выбранного периода. При отсутствии периода quarter_summary=null. outstanding_documents остаётся суммой остатков всех уникальных исходных периодов. latest_snapshot сохраняет значение из ADR-0005.
4. Фильтры выполняются в PostgreSQL до total и LIMIT/OFFSET. Процент сравнивается без округления, с numeric-арифметикой; отображаемое JSON-число может иметь обычную погрешность представления дроби. Округление для интерфейса не меняет выборку.
5. Автоматические проверки Clients включают линтер, полный набор тестов с PostgreSQL и отдельный build/start контейнера на GitHub Actions. Публикация образа и развёртывание не выполняются. До реального запуска workflow его наличие не считается доказательством успешной сборки.

## Consequences

Схема БД не меняется. Обновляются контракты, требования и инструкция. Межсервисная авторизация не реализуется в этом этапе: документ proposals/clients-service-auth.md имеет статус Proposed. Gateway, Import и Operator Work остаются отдельными реализациями; новые тесты показывают сквозную работу только HTTP-контракта Clients.
