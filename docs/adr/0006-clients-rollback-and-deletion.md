# 0006. Локальный откат и ручное удаление Clients

## Status

Accepted — решения пользователя от 07.11.2026. Последний ответ «восстановить» отменяет предварительное предложение о приоритете ручного удаления.

## Context

Данные и undo применения пакета уже атомарны в Clients DB. Нужно выполнить восстановление и удаление, сохранив роль Import как координатора. Если после импорта данные удалили вручную, пользователь выбрал восстановление при откате этого импорта.

## Decision

1. Откат восстанавливает состояние затронутых пакетом клиентов до его применения. Он восстанавливает и данные, вручную удалённые после этого пакета. Клиенты, которых пакет не затрагивал, не восстанавливаются. Новая загрузка после удаления разрешена.
2. Import обязан проверить последний применённый пакет всей системы и координировать соседние сервисы. Clients дополнительно запрещает откат более раннего активного локального пакета. Локальный ответ не означает завершения всей системы.
3. Для новых пакетов фиксируется монотонный apply_order под общим advisory lock. Для старых пакетов до миграции порядок не выдумывается из времени: единственный оставшийся старый пакет допускается, несколько старых активных пакетов дают IMPORT_ORDER_UNKNOWN до восстановления порядка координатором. HTTP-включение на общем стенде до этого запрещено.
4. operation_id — ключ повтора отката/удаления. Повтор идентичной команды возвращает сохранённый результат; другой запрос с тем же ID даёт 409. Повтор отката уже отменённого пакета с новым ID также не меняет данные повторно. Повтор apply отменённого batch_id запрещён.
5. Удаление отсутствующего клиента/квартала успешно с нулевыми счётчиками. При квартальном удалении удаляются только актуальный срез, его история и происхождение; остальные периоды, профиль, теги и общая операторская история сохраняются. Производные показатели пересчитываются чтением.
6. После ручного удаления история исчезает из рабочих таблиц/API. Для выбранного восстановления её содержимое сохраняется в закрытом undo удаления; обычный технический журнал содержит только автора, объект, время и результат. Undo недоступен через Registry API. Это обратимое административное удаление, а не гарантированное уничтожение резервных копий.
7. Undo импорта восстанавливает профиль, теги, актуальные срезы и происхождение. Из обычной истории удаляются наблюдения откатываемого пакета. Из undo последующих удалений восстанавливаются прежние наблюдения затронутых клиентов, исключая откатываемый и уже отменённые пакеты. Исходные ID и порядок наблюдений сохраняются.
8. Apply, rollback и delete используют один локальный lock и транзакцию: данные, состояние пакета, undo удаления и результат команды фиксируются вместе. Ошибка оставляет команду неприменённой; повтор после потери ответа безопасен. Новый operation_id означает новую команду, а не повтор старой.
9. HTTP rollback/delete выключен по умолчанию отдельным переключателем для изолированной разработки. Клиентская роль/флаг в теле не считаются подтверждением полномочий Import; межсервисная авторизация и глобальная проверка ещё не реализованы.

## Consequences

Добавляется миграция Clients DB и отдельный внутренний протокол. Работа Operator Work и кэши других сервисов здесь не изменяются. Координатор должен сериализовать глобальные операции, сохранять operation_id и доводить очистку/восстановление до конца; финальный публичный успех допустим только после этого. Физическое уничтожение undo и правила срока его хранения требуют отдельного согласования и не выполняются этим этапом.
