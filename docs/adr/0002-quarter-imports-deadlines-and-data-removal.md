# 0002. Квартальные данные, ожидание срока и удаление

## Status

Accepted — уточнения пользователя в чате от 05.11.2026.

## Context

ADR-0001 сохраняется как исходное архитектурное решение. Поздние комментарии заказчика к UC-08–UC-11 и уточнения пользователя меняют бизнес-процесс, жизненный цикл данных и размещение ИИ. Они имеют приоритет над ранними формулировками сценариев.

## Decision

1. UC-08, UC-10 и UC-11 исключены; оператор сам выбирает, кому и когда звонить.
2. При загрузке явно выбирается квартал. Используются только квартальные периоды; годовые агрегаты из исторического Excel не моделируются как периоды.
3. Непереданные документы сохраняются по исходному кварталу и учитываются дальше без повторного суммирования. От двух кварталов непрерывной задержки — LONG_DELAY_2Q.
4. WAIT_DEADLINE защищает ответственного до даты оператора, включая смену квартала. После срока при остатке клиент вновь доступен. Смена квартала не продлевает срок.
5. Пустые поля наследуются с происхождением и меткой проверки; явные ноль/false сохраняются.
6. Отменяется последний пакет. Ручное удаление разрешено; удалённые данные убираются и из начатой работы операторов. Обычное append-only хранение имеет эти явные исключения.
7. ИИ работает через облачный API стороннего провайдера. Конкретные функции и модель пока не согласованы.

## Consequences

Обновляются ТЗ, spec.md, API и DDL четырёх существующих доменных хранилищ; границы микросервисов не меняются. Межсервисная очистка требует идемпотентного протокола и не может оставлять действующие назначения без исходных данных. Актуальные правила и отложенные вопросы перечислены в spec.md 1.4.
